# Баланс

Статический дневник питания и веса: без сервера, регистрации и сборки. Работает как PWA на GitHub Pages и офлайн. Данные остаются в localStorage браузера; синхронизации между устройствами нет.

## Версия 2

- Главная: компактная карточка динамики над календарём, навигация по месяцам и быстрые кнопки записи дня / измерений. Ячейки компактные и не растягиваются на свободную высоту; на небольших экранах календарь уменьшается, чтобы поместиться без прокрутки. Тренд, план, привычка и недельный обзор доступны во вкладке «Мой план».
- Вес, талия, время, условия взвешивания и заметка о силовых показателях сохраняются отдельно от питания.
- Дни питания: «Внесена часть», «День завершён», «Полнота не проверена». Старые записи автоматически не объявляются полными. Пропущенный день означает неизвестность.
- Дефицит считается оценкой. Старые записи с непроверенной полнотой показываются в графике и накопленной сумме; явно неполные дни исключены. Старые дни не становятся подтверждёнными: в калибровке используются только завершённые дневники. Чрезмерный дефицит не получает зелёную оценку.
- Единый график с вкладками калорий, нутриентов, веса и грубого энергетического эквивалента оставшейся массы. У веса есть линия тренда. Можно скрывать линии и просматривать таблицу.
- План задаётся темпом и диапазоном питания; желаемый дедлайн не повышает ограничения. Есть режим удержания с выбранным центром диапазона ±1 кг.
- Недельный обзор предлагает одно действие. Уточнение оценки расхода доступно только при достаточных данных и применяется пользователем.
- Шаблоны продуктов, рецепты с массой ингредиентов и выходом готового блюда, добавление порции по граммам и повтор вчерашних продуктов без дублирования.
- Для продуктов сохраняются источник, выбранные калории и необязательный исходный диапазон оценки. Шаблон не меняет старые порции.
- Необязательные шаги, сон, голод, энергия и время на учёт. Тренировки не прибавляются повторно к суточному расходу.
- История планов и сохранённых обзоров, полная резервная копия и проверяемый отчёт с исходными наблюдениями.

## Расчёты и границы применения

Формула обмена: `10 × вес + 6,25 × рост − 5 × возраст + коэффициент` (+5 или −161, выбирается в профиле). Множители активности: 1,2 / 1,35 / 1,55; пользователь может указать расход дня вручную. Формула — стартовая оценка, не измерение обмена. Месячная база использует последнее взвешивание строго до начала периода, привязанного к дате старта. Для 31 числа в коротком месяце берётся последний день; затем исходное число восстанавливается.

Прогресс основан только на измеренном весе. Повторный одинаковый вес считается новым наблюдением. Расчётные калории не добавляют выдуманные потерянные килограммы. Коэффициент 7700 ккал/кг используется как грубое приближение, а не как динамическая физиологическая модель.

Тренд: среднее доступных измерений за последние 7 календарных дней, минимум 3 измерения. Темп: медиана попарных изменений с интервалами ≥7 дней в окне 28 дней; нужны ≥4 измерений, интервал ≥14 дней и свежее измерение за неделю. Исходные точки сохраняются. Сценарный диапазон дат строится только при наблюдаемом снижении; он не является обещанием или статистическим доверительным интервалом.

Начальные настройки: желаемый темп 0,5 кг/нед., нижняя граница питания 1500 ккал. Дефицит ограничен меньшим из: выбранный темп ×7700/7, 500 ккал, 20% расхода, разница расхода и нижней границы питания. Диапазон питания — около расчётной цели ±100 ккал, с округлением до 50 и ограничением снизу. Это продуктовые ограничения, не индивидуальные медицинские назначения. Автоматического уменьшения питания нет. После дедлайна формула не делит остаток на один день.

Калибровка расхода: завершённые дневники по вчерашний день, окно до 28 дней, ≥21 календарного дня, ≥85% завершённых дней, ≥6 взвешиваний с интервалом ≥21 дня. Оценка `среднее потребление + темп снижения ×7700/7` не отделяет ошибку учёта еды от расхода и изменений воды. Рабочий диапазон учитывает разброс темпа и минимум ±200 ккал / ±10%; это не доверительный интервал. Предложение изменяет расход не более чем на 100 ккал и не чаще одного раза в 7 дней после изменения плана; плохая переносимость блокирует предложение. Старые записи сохраняют снимки расхода и цели, новые настройки действуют с даты принятия.

Источники подхода: [NIDDK Body Weight Planner](https://www.niddk.nih.gov/health-information/weight-management/body-weight-planner), [NICE NG246](https://www.nice.org.uk/guidance/ng246). Приложение не реализует физиологическую модель NIDDK и не обещает медицинскую эффективность.

## Данные, обновление и проверка результата

Ключ localStorage остаётся `balance-v1`; внутренняя `schemaVersion: 2`, версия алгоритма `2.0.0`. Перед миграцией создаётся точная копия в `balance-before-v2`. Если создать или сохранить копию не удаётся, миграция не завершается. В «Мой план» можно скачать исходную копию. Старые записи сохраняют питание, вес и расход, полнота становится непроверенной.

Полная копия v2 содержит профиль, дневник, измерения, рецепты, привычку, протокол проверки, историю планов и обзоров. Восстановление валидируется до замены; перед заменой сохраняется `balance-before-restore`. Старые копии v1 поддерживаются. Импорт ИИ не закрывает день автоматически; отмена проверяет, что после импорта не изменилось всё состояние, включая измерения и привычки.

В «Мой план» задаётся начало личного наблюдения: 14 дней исходного периода и 56 дней проверки. JSON-отчёт содержит исходные данные, пропуски, покрытие дневника, вес и талию, голод, энергию, сообщённое время на учёт и историю решений. Сравнение одного человека до/после не доказывает причинный эффект приложения. Изменения тела подтверждаются внешними измерениями и временем; автоматические тесты подтверждают только работу программы.

Данные включают сведения о здоровье. Экспорт скачивается локально; не публикуйте личный JSON в репозитории. Копирование промпта само по себе ничего не отправляет в ИИ.

## Запуск и публикация

Для просмотра: `python3 -m http.server 8080`, затем `http://localhost:8080`. Для приложения сборка и npm не нужны. Офлайн-ресурсы перечислены в `sw.js`; актуальный кеш — `balance-v17`.

GitHub Pages: Settings → Pages → Deploy from a branch → `main` → `/ (root)`. Все ссылки относительные, приложение работает в подпапке `/balance/`. Android: меню браузера → Установить приложение. iPhone: Поделиться → На экран «Домой».

## Проверки

Нужен Node.js ≥22. `npm ci`, затем `npm test` — модель, интеграция расчётов и хранения, прежние импорты, промпт, компактный формат и графики.

Браузер: `npx playwright install --with-deps chromium`, запустить HTTP-сервер, затем `npm run test:browser`. Можно указать `BALANCE_TEST_URL`, `PLAYWRIGHT_CHROMIUM_EXECUTABLE`, `BALANCE_SCREENSHOT`. Проверяются миграция, независимые измерения, полнота дня, шаблоны/диапазоны, рецепты, импорт/отмена, история, удержание, копия/восстановление, отчёт, ширины 320/390/768 px и офлайн.

Код расчётов изолирован в `balance-model.js` и не зависит от DOM, сети или ИИ. `management.js` содержит сценарии измерений, планов, обзоров и шаблонов. Существующие контракты: [импорт](docs/chatgpt-import.md), [промпт](docs/ai-prompt.md), [компактный формат](docs/compact-import.md).
