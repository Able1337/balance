# Balance: импорт из ChatGPT (v1)

Импорт из ChatGPT и ссылки с предпросмотром. Расширение нутриентов и копируемый промпт описаны в ai-prompt.md.

## Использование

На главной нажмите **Импорт / экспорт ChatGPT**, вставьте JSON, нажмите **Проверить и посмотреть**. Выберите объединение или замену, проверьте итоги и подтвердите. В «Мой план» есть та же кнопка. Для экспорта выберите одинаковые даты (один день) или период и скачайте JSON. Существующая полная резервная копия дневника сохранена.

Ссылка `https://able1337.github.io/balance/#import=<payload>` открывает предпросмотр автоматически. Данные сохраняются только после подтверждения. При первом запуске сначала заполните профиль: ссылка останется до окончания настройки. После успешного импорта, отмены или ошибки fragment убирается через `history.replaceState`; путь и query сохраняются. Android может открыть обычную вкладку Chrome вместо установленного PWA: выберите приложение вручную или вставьте JSON внутри него. Принудительный запуск установленного PWA не реализуется.

## JSON для вставки / экспорта

Одна запись, массив записей или `{ "days": [...] }`, максимум 366 уникальных дат за операцию. Каждая запись:

```json
{
  "schemaVersion": 1,
  "date": "2026-10-18",
  "foods": [{
    "id": "20261018-lunch-chicken",
    "name": "Куриное филе",
    "status": "consumed",
    "weightGrams": 450,
    "calories": 509,
    "protein": 103,
    "fat": 10,
    "carbs": 0,
    "accuracy": "Оценка по справочнику"
  }],
  "exercises": [{
    "id": "20261018-walk-1",
    "name": "Ходьба на дорожке",
    "status": "completed",
    "durationMinutes": 30,
    "speedKmh": 5,
    "inclinePercent": 5,
    "activeCalories": 250,
    "totalCalories": 290
  }],
  "dailyExpenditure": 2800,
  "targetDeficit": 784,
  "comments": "В суточный расход уже включена тренировка",
  "accuracy": "Приблизительная оценка"
}
```

Обязательны `schemaVersion: 1`, `date`. `foods`, `exercises` необязательны, по умолчанию пустые. У еды обязательны `name`, `weightGrams`, `calories`, `protein`, `fat`, `carbs`; БЖУ — граммы, калории — ккал всего продукта данной массы, не на 100 г. Статус еды `consumed` (по умолчанию) или `planned`. У тренировки обязательно только `name`, статус `completed` (по умолчанию) или `planned`. Остальные поля тренировки необязательны.

У строк необязательны `id`, `comments`, `accuracy` (строки). `accuracy` — комментарий о точности, а не числовая гарантия. В дне необязательны `dailyExpenditure`, `targetDeficit`, `weight` (кг), `comments`, `accuracy`. Неизвестные поля отклоняются.

В экспортируемом дне есть `actualTotals: {"calories": 2000, "protein": 160}` — итоговые фактические калории и белок, включая ручную часть. Это позволяет без потерь импортировать старые записи, где продуктов нет. Если `actualTotals` передан, он авторитетен для этих двух итогов, независимо от списка еды. Не добавляйте его при обычном описании нового приёма пищи.

Дата — реальная календарная дата ISO `YYYY-MM-DD`, не раньше старта плана и не позже сегодня. Числа конечные, неотрицательные: обычные поля до 20 000, клетчатка до 1 500 г, масса до 100 000 г, вес 20–500 кг. Суточный расход строго положительный. Итоги: до 20 000 ккал и 1 500 г белка. Активные калории не должны превышать общий расход тренировки, если указаны оба. Максимум 500 продуктов и 500 тренировок на день, строки до 4 000 символов. JSON для вставки до 200 000 символов. Значения `null`, числовые строки, отрицательные числа не принимаются в этих полях.

## Точный контракт ссылки

Один день в одной ссылке. Используется `version` вместо `schemaVersion`; обязательны уникальный `importId` и `mode`:

```json
{
  "version": 1,
  "importId": "20261018-lunch-7f29c1a0",
  "date": "2026-10-18",
  "mode": "append",
  "foods": [{"id":"lunch-chicken-1","name":"Куриное филе","weightGrams":450,"calories":509,"protein":103,"fat":10,"carbs":0}],
  "exercises": [],
  "dailyExpenditure": 2800
}
```

Остальные допустимые поля совпадают с контрактом дня выше. `mode`: `append` или `replace` (только начальный выбор в предпросмотре; пользователь может изменить его). `importId`: 8–128 символов `A–Z a–z 0–9 _ -`, новый случайный UUID/идентификатор для новой операции. При повторной передаче той же операции сохраняйте **тот же** ID, даже если ссылка отправлена ещё раз. Для исправления операции используйте новый importId и прежние стабильные id строк. История ID хранится вместе с дневником; повторная ссылка не записывается. Поддельный importId не даёт никаких прав: это локальный ключ дедупликации, не токен доступа.

Без id строк точные совпадения нормализованных полей не дублируются, но изменение названия/массы воспринимается как новая строка. Для двух одинаковых порций используйте разные id. При совпадении id строка обновляется. Продукты разных статусов без id — разные строки.

## UTF-8 → Base64URL

1. Сериализовать объект через `JSON.stringify`.
2. Закодировать текст в UTF-8 (`TextEncoder` или Python `.encode('utf-8')`).
3. Выполнить Base64 над **байтами**, заменить `+` на `-`, `/` на `_`, убрать завершающие `=`.
4. Добавить к `https://able1337.github.io/balance/#import=`.

JavaScript (локально, без сервера):

```js
const bytes = new TextEncoder().encode(JSON.stringify(data));
let binary = '';
for (const byte of bytes) binary += String.fromCharCode(byte);
const payload = btoa(binary).replaceAll('+', '-').replaceAll('/', '_').replace(/=+$/, '');
const url = 'https://able1337.github.io/balance/#import=' + payload;
```

Python:

```python
import json, base64
payload = base64.urlsafe_b64encode(
    json.dumps(data, ensure_ascii=False, separators=(',', ':')).encode('utf-8')
).decode('ascii').rstrip('=')
url = 'https://able1337.github.io/balance/#import=' + payload
```

Готовый небольшой пример (фиктивный пустой день, сначала только предпросмотр):

[Открыть пример](https://able1337.github.io/balance/#import=eyJ2ZXJzaW9uIjoxLCJpbXBvcnRJZCI6ImV4YW1wbGUtMjAyNjEwMTgtMDAxIiwiZGF0ZSI6IjIwMjYtMTAtMTgiLCJtb2RlIjoiYXBwZW5kIiwiZm9vZHMiOltdLCJleGVyY2lzZXMiOltdfQ)

Лимит payload — 12 000 символов Base64URL (примерно 9 КБ исходного UTF-8 JSON). Длинные URL могут обрезаться мессенджером/браузером раньше; для надёжности держите ссылку короче 2 000 символов. Большие дни и несколько дат передавайте вставкой JSON. ChatGPT без вычислительных инструментов может ошибиться при ручном Base64: в этом случае используйте вставку JSON.

## Инструкция для ChatGPT

```text
Подготовь запись для Balance за [ДАТА] по нашему обсуждению. Отдели фактически съеденное от запланированного. Для каждой еды укажи name, weightGrams, calories, protein, fat, carbs (итоги для данной массы), status consumed или planned и стабильный id. Для тренировок раздели activeCalories и totalCalories, status completed или planned. Не прибавляй тренировку повторно к dailyExpenditure: это полный расход за сутки. Не выдумывай общий расход, если данных нет. Оценки пометь accuracy и comments.
Сформируй объект {version:1,importId:<новый UUID>,date:"YYYY-MM-DD",mode:"append",foods:[...],exercises:[...]}; при наличии добавь dailyExpenditure и targetDeficit. Используй только поля контракта Balance. Для той же операции повторно используй прежний importId, для исправления создай новый ID, сохрани id продуктов. Закодируй JSON в UTF-8, затем Base64URL без '=' с помощью Python/JS, сформируй Markdown-ссылку https://able1337.github.io/balance/#import=<payload>. Не кодируй Unicode напрямую через btoa. Если инструментов кодирования нет или payload длиннее 12000 символов, дай обычный JSON со schemaVersion:1 (без version/importId/mode), пригодный для вставки в приложение. Сохранение пользователь подтвердит в Balance.
```

## Совместимость, расчёты и безопасность

- Старые агрегаты остаются в `entries[date]`. Расширение — `chatgpt` с продуктами, тренировками, комментариями и `baseline` для ручной части. Расчёты календаря и графиков используют прежние `intake`, `protein`, `mode`, `spent`, `weight`.
- Объединение добавляет продукты к прежнему ручному итогу. Замена заменяет питание и детали; вес и расход сохраняются, если не переданы. Чужие даты не меняются. Ручное редактирование итогов сохраняет детали и корректирует baseline.
- Только consumed входит в итог еды. Тренировки описательные: ни activeCalories, ни totalCalories автоматически не прибавляются к расходу. `dailyExpenditure` переключает день на собственный расход. `targetDeficit` — импортированная заметка, месячный план не меняет.
- Перед каждой фактической записью импорта сохраняется полная копия в `balance-before-chatgpt-v1`. Если копия не помещается, импорт блокируется. Полное состояние дневника остаётся в `balance-v1`; `importIds` — история операций. Отмена восстанавливает состояние до последнего импорта, включая ID; если дневник после импорта изменён, отмена блокируется, предлагается скачать копию до импорта.
- Данные из fragment не отправляются серверу приложением. Base64URL **не шифрование**: получатель ссылки и история браузера могут прочитать данные. Импорт не содержит сетевых запросов, ключей или доступа к приватным чатам. Импортированные строки экранируются при показе.
- Обычный экспорт периода не включает importIds, полная резервная копия включает. Восстановление полной копии сохраняет записи и историю importIds, если она есть в файле. В старых копиях истории нет; после их восстановления защита по ID не гарантируется (дедупликация строк остаётся).
- Новые файлы включены в офлайн-кэш `balance-v7`. Обновление PWA применяется при новом service worker. Для реального Android нужны отдельные проверки на устройстве после разрешённой публикации: установка, открытие ссылки Chrome/PWA, работа офлайн.

## Дополнение нутриентов
foods[].fiber — необязательная клетчатка в граммах всей порции. actualTotals поддерживает необязательные fat, carbs, fiber. Дневная форма и графики поддерживают эти показатели. Подробности: [Промпт и нутриенты](ai-prompt.md).
