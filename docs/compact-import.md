# Компактный импорт v2

Новый формат входящих ссылок и JSON уменьшает размер за счёт однобуквенных ASCII-ключей, целых чисел, коротких названий и пропуска необязательных данных. Старый v1 и внутреннее хранилище не изменены. Экспорт полной истории остаётся в совместимом подробном формате v1.

```json
{"v":2,"i":"a19d72cf408b","d":"2026-10-22","m":"a","f":[{"i":"f01","n":"Сосиска 1/5","g":12,"k":35,"b":1,"j":3,"u":1,"c":0,"z":1,"q":"60/5=12г"}]}
```

| День | Значение |
|---|---|
| v | Версия, всегда 2 |
| i | importId: 8–128 ASCII-букв, цифр, `_` или `-`; рекомендуется случайный 12-символьный hex |
| d | Дата `YYYY-MM-DD` |
| m | `a` добавить, `r` заменить питание дня |
| f / e | Массив продуктов / тренировок, можно пропустить пустые |
| x / t | Полный суточный расход / целевой дефицит, ккал |
| w | Измеренный вес, кг; не передавать без просьбы записать взвешивание |
| z | 1 — оценка, 0 — этикетка/измерение |
| q | Краткое примечание |
| a | Полные агрегаты при восстановлении, объект с k,b,j,u,c; не использовать для обычного добавления еды |

| Продукт | Значение |
|---|---|
| i / n | Стабильный id / краткое понятное название |
| g | Масса съеденной порции, граммы |
| k / b / j / u / c | Калории / белок / жиры / углеводы / клетчатка |
| s | 1 — запланировано; 0 — съедено (по умолчанию, можно не передавать) |
| z / q | Точность / краткое допущение |

В продукте обязательны n,g,k,b,j,u,c; i настоятельно рекомендуется для дедупликации и исправлений. Названия и значения нутриентов относятся ко всей порции, не к 100 г.

Тренировка: i=id, n=название, t=минуты, a=активные ккал, k=общие ккал, v=скорость, h=уклон, s=1 план/0 выполнено, z=точность, q=примечание. Отсутствующие сведения не передаются. Активные калории не прибавляются автоматически к x.

Все числа v2 округляются до ближайшего целого (0.5 вверх), включая импорт, если ИИ прислал дроби. Масса положительной порции после округления — минимум 1 г. Отрицательные и неконечные числа, числовые строки, неизвестные ключи, неправильные даты и пропущенные нутриенты отклоняются. Проверка выполняется после разворачивания в обычную модель v1. Старый формат продолжает принимать дроби; существующие измерения не округляются задним числом.

Одно действие v2 — одна дата. Можно открыть ссылку `#import=<Base64URL UTF-8 JSON>` или вставить сам компактный JSON. Правила подтверждения, importId, отмены и резервной копии прежние. Для нескольких дат выдавайте отдельные операции; для пакетного старого импорта остаётся v1.

## Требования к ИИ

Промпт приложения требует:
1. Использовать только компактные ключи для новых ссылок, без длинных повторяющихся комментариев и истории профиля внутри URL.
2. Считать с полной точностью, округлять готовый JSON до целых. Предпочтение верхней разумной границы приблизительных калорий сохраняется.
3. Реально исполнить код сериализации UTF-8 → Base64URL, затем декодировать и сравнить объект с исходным через `assert decoded == data`.
4. Проверить поля, дату, id, режим, числа и обязательные нутриенты. Проверка JSON не является сетевой проверкой страницы.
5. При отсутствии вычислительного инструмента или неудачной проверке выдавать JSON, не угадывать Base64.
6. Предпочитать JSON, если payload длиннее 2000 символов; лимит приложения 12000. Рядом с проверенной ссылкой давать резервный компактный JSON.

Пример одинаковых данных в тесте: payload v1 410 символов, v2 211 символов (на 49% короче). Степень сокращения зависит от названий и содержания. Сокращение не исправляет ошибки, которые ИИ внесёт при ручном кодировании.

## Проверки

`node test-compact.cjs`: отображение ключей дня, еды и тренировок, целые числа, UTF-8, обычная вставка и ссылка, id/режим, идемпотентное добавление, roundtrip и отрицательные сценарии. `node test-import.cjs`: прежние 22 теста v1. `node test-prompt.cjs`: актуальные параметры, прежние правила питания, компактный контракт, округление и обязательная обратная проверка.
